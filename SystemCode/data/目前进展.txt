目前建模进展：
我们发现这个数据存在非常严重的类别不平衡问题。Validation data 中大约 97% 都是 C0（未来 48 个时间单位内没有维修），所以如果模型无脑把所有车辆都预测成 C0，也能得到约 97% Accuracy。因此这里不能单纯用 Accuracy 判断模型好坏。

我们之后加入了车辆历史变化的 Temporal Features（例如前后读数变化和变化速率），并调整了训练数据的 sampling，避免同一辆车的大量历史 C0 记录把其他类别淹没。

调整后，对最紧急的 C4（0–6 个时间单位内发生维修），Recall 从 2.6% 提升到了 26.3%，说明模型开始真正识别接近维修的车辆。

接下来我们测试了不同程度的 class weighting，用来平衡两个业务风险：漏掉真正快坏的车和产生太多不必要的维修警报。目前轻度加权效果最好，C4 Recall 提升到 34.2%，同时在测试的方案中取得了最低的维修决策 Cost（44,320）。继续增加权重虽然可以把 C4 Recall 提高到 43.4%，但会产生太多误报，因此总体 Cost 反而没有继续下降。

**目前结论：**这个项目真正的问题不是追求最高 Accuracy，而是在 “尽量不要漏掉即将维修的车辆” 和 “不要产生太多错误维修警报” 之间找到最佳平衡。目前 Vehicle-aware sampling + Temporal XGBoost + Light Class Weighting 是我们测试中业务 Cost 最低的方案。
